# Visual Bible — 《余光街区 / Afterlight District》

## 1. Visual thesis

- **游戏与玩家**：面向手机竖屏轻度策略玩家的三维生存经营守城游戏。
- **情绪承诺**：玩家不是让数字变大，而是在黑暗中亲手恢复一小块有人生活的街区。
- **一句话视觉命题**：所有进度都表现为“光从发电机沿街道向外扩张”。
- **标志性时刻**：设施修复后，青绿色电流沿地面线路传播，窗口和路灯依次亮成暖金色。
- **三个必需品质**：黑暗中仍清晰；低多边形模型像同一套世界；每次教学动作都有场景反馈。
- **三个禁止方向**：中世纪城堡换皮；霓虹赛博朋克；通用玻璃卡片式手游 HUD。

## 2. Composition and camera

- **方向与尺寸**：手机竖屏，主验收 390×844，窄屏 320×568；使用响应式 DOM HUD 包围可缩放 Three.js 场景。
- **相机**：以约 42° 正交等距轴为主，但不再固定为一个全局沙盘机位。建立镜头 zoom 80、较高俯角；救援中近景从反侧无障碍观察轴切入，zoom 88–92；工作台中景 zoom 90–94；路障道路中景 88；黄昏/夜袭全景 76；结算 82。镜头在 420–650ms 内平滑切换焦点，玩家不能自由旋转。每个教学机位必须同时看见目标、角色和周边空间，不得只剩目标局部；同时检查前景建筑/树冠遮挡并禁止相机穿模。
- **场景尺度**：不再用重复地块或数块高差草坡拼接画面。正式地形是一块 15×18 世界单位的连续地基，消费端保持 1:1 比例；建筑高度为成人角色的 1.65–2.15 倍。390×844 与 320×568 的 platform-layout 镜头内不得看见地形外缘和底部断面，玩家应理解为“街区的一部分”而不是悬浮模型板。
- **开场唯一主焦点**：受困信号屋占上方左侧三分之一，唯一亮窗、卡死门和屋顶信号冠构成最亮簇；值守员乔位于前景，连续服务路与断裂青绿电缆共同把视线从乔引向门口。开场至少保留约 45% 无高物件负空间。
- **分阶段层次**：开场只显示连续地形、信号屋、背景脊线、乔和最多两处低矮环境剪影；发电机、工作台、路障和中继灯在各自教学步骤到来前不出现。经营阶段才形成“人物—岗位—发电机”中景，夜袭阶段才展开完整防线。
- **密度上限**：同一镜头内最多 1 个主建筑、2 个次级高物件和 3 组低矮环境细节；禁止每个地块重复草叶、石块和路缘。细节以 0.75–1.5 世界单位为簇间距，连续空地必须大于一个成人角色的两倍宽度。
- **空间展开**：主建筑与最近设施之间至少留 1.6 个成人身高的水平距离，两盏中继灯之间至少留 2.6 个成人身高。镜头通过分阶段目标点切换保持角色可读，禁止为了看全场重新缩成棋盘总览。
- **HUD 安全区**：顶部约 91px 为昼夜与低噪声资源轨；教学阶段在其下只出现一条随文字收缩的“当前任务”。底部按阶段容纳人物对话或居民调度。对话是剧情镜头的一部分，不是覆盖中景的通用说明卡。
- **注意路径**：当前教学目标 → 因动作产生的光或移动 → 顶部资源变化 → 下一目标。

## 3. Color

- **背景**：Blackout `#111821`；远景 Night Slate `#26323D`。
- **表面**：Panel Ink `#182129`；抬升表面 `#25323B`；边线 `#40515A`。
- **文字**：Paper `#F4EFE4`；次要文字 `#A9B5B8`。
- **电力与可操作**：Power Teal `#3FB6AC`；成功与已通电不能只靠颜色，需同时显示线路与图标状态。
- **灯光与奖励**：Warm Window `#FFD58A`。
- **危险**：Danger Coral `#D85B4B`，同时配合三角缺口、震动或警示文案。
- **使用比例**：暗背景与环境 72%，暖灯 15%，中性 UI 9%，青绿交互 3%，危险珊瑚 1%。
- **禁止组合**：大面积青绿渐变；紫蓝霓虹；纯黑上的低对比灰字；红绿二元状态无形状辅助。

## 4. Typography

- **标题**：`Arial Narrow`, `Roboto Condensed`, `PingFang SC`, sans-serif，700，轻微 0.02em 字距。
- **UI/正文**：系统无衬线、`PingFang SC`、`Microsoft YaHei`，500/600。
- **数字/HUD**：`ui-monospace`, `SFMono-Regular`, monospace，700，使用等宽数字。
- **尺寸**：游戏名 30–36px；引导标题 18px；正文 15–16px；资源数字 14px；非交互微标 11–12px。
- **规则**：不使用全大写长句；不使用描边字和多层阴影；正文最多两行，每行中文不超过 16 字。

## 5. Shape, material, and lighting

- **形状**：场景资产继续使用硬边方体、低段圆柱和 45° 切角；界面改用 12–22px 的饱满圆角、双层描边和略微鼓起的玩具按钮。功能区域不使用无边界胶囊。
- **边框与阴影**：界面使用 2px 深可可紫描边、1–2px 暖白内高光和 3–5px 实体底托；场景仍以自然阴影接地。禁止玻璃、霓虹和模糊阴影堆叠。
- **材质**：共享 GLB 的 flat-shaded `MeshStandardMaterial`；不统一替换材质，不增加写实纹理。
- **灯光**：环境光只负责保留暗面信息，不能代替灯具。白天环境/半球光强约 0.08/0.32，夜间降至约 0.055/0.22；方向主光白天 2.92、夜间 1.78，并始终保留 0.09–0.14 的冷 fill 与 0.22–0.34 的暖 rim，维持顶面/近侧/远侧三值。每个可见 emissive 灯具必须有同位置、同颜色语义的真实局部光：受困屋唯一暖窗使用半径约 3.8u 的暖黄点光；发电机使用半径约 3.0u 的低饱和青绿点光；两盏中继灯各使用半径约 4.0u、强度 13 的暖黄点光。过载时中继灯切换为灰青 `#70D4C8`、强度 18，并以 8% 幅度脉冲。
- **光池与光源**：窗户、发电机和中继灯先用小型 `SourceHalo` 说明光从哪里发出，再在地面提供更弱、软边的椭圆辅助光池；实际模型受光必须来自 `PointLight`。光池透明度不得高于过载时 0.16，禁止用高饱和圆斑冒充照明。禁止只有 emissive 材质、没有环境受光变化的“贴纸灯”；也禁止无可见来源的中央万能点光。
- **供电路径**：通电线路由 8 段嵌地短导管组成，按相位依次改变 emissive，表达电流传播。禁止使用一整块贯穿场景的发光平面，避免线路压过人物和灯区。
- **接地**：建筑、地形和设施在 balanced/high 使用 2048² 软方向主光阴影，low 使用 1024²；阴影强度约 0.36。全场使用分档 GTAO 加深屋檐、窗框、梁柱与地面交界。人物和怪物不投射大块长方向影，依靠 GTAO 与模型交界保持接地，禁止人物黑影成为第二焦点。
- **后处理与抗锯齿**：使用 `RenderPass → GTAOPass → UnrealBloomPass（low 关闭）→ OutlinePass → SMAAPass → OutputPass`。low / balanced / high 分别使用 6 / 9 / 12 GTAO samples、0 / 2 / 4× MSAA 和 1–1.25 / 1–1.6 / 1.5–2 DPR；SMAA 三档保留，保证低档降性能而不是退化为明显锯齿。Bloom 只允许作用于灯芯与过载峰值，常态强度不高于 0.08、过载不高于 0.14，禁止将白色灯芯烧成无结构光团。地面大平面可使用不超过约 6% 值差的宏观明度贴图，但不得出现写实噪点或重复纹理。
- **选择性漫画勾边**：使用屏幕空间选区遮罩，不复制反面外壳、不替换 GLB 材质。可见边使用近黑紫 `#100E12`，强度 1.6、正常透明混合、无 glow，再交给 SMAA 收边。low 只选择当前交互目标（thickness 3.2）；balanced 选择目标、人物与敌人（3.0）；high 再加入主信号屋（4.0）。按各档 DPR 与 downsample 折算后，手机成图约为 1.5–2 CSS px，必须在 320px 宽截图中不放大即可辨认。地形、道路、远景脊线、灯光光池和普通设施禁止勾边，避免整场变成密集线稿；隐藏边 alpha 固定为 0，不得形成隔墙透视线。
- **自动降档**：初始档位参考 `deviceMemory`、`hardwareConcurrency`、DPR 和 Save-Data；每 4 秒统计一次真实帧率，连续两个窗口低于 42 FPS 时只降一级，并在降档后冷却 8 秒。QA 可用 `?render_quality=low|balanced|high` 锁档，生产 UI 不显示技术档位。

## 6. Characters, environments, and assets

- **角色比例**：保留共享模型各自轮廓和静止姿态；岗位状态通过位置、工具与小型地面标记表达。
- **动作范围**：待机呼吸、挥手求救、指向目标、双臂交替工作、僵尸不对称拖步与低伏怪物疾行。世界位置与动作位移必须使用内外两层 Group，起伏不得覆盖角色的落地高度；所有肢体只相对 GLB rest pose 叠加。
- **救援演出**：引导阶段林的声音从信号屋内传出，实体模型不穿墙展示；乔在前景指向目标。搜救开始后乔移到门外安全区执行双臂工作动作。3.2 秒进度按物理因果分段：前 52% 让 `state_doorBrace` 落到门槛外，后 50% 再驱动 `state_signalDoorPivot` 向外开启 1.18rad；进度超过 72% 后，林才在门外右侧安全点出现。门板、门闩、乔和林彼此保留清晰间距，救援完成后门保持开启。
- **教学演员**：工人“林”负责表达受困、获救和岗位能力；值守员“乔”负责观察威胁并给出短口令。两人同时使用场内 GLB 与从同一正式 GLB 离线渲染的透明胸像立绘，禁止用全身预览缩略图、无人物归属旁白或另一套人物画风替代他们。
- **专属资产优先**：林、乔、信号屋、中继灯、熄光壳和缆猎者必须使用本作专属 builder 身份。通用 worker/securityGuard/house/lamp/zombie/werewolf 仅保留为早期对照，不得出现在正式切片。
- **造型母题**：所有专属身份都从“断电基础设施被重新点亮或反向吞噬”出发：三触点、母排、插头、缆线、继电器笼、信号冠。不能只给通用模型换 teal 颜色。
- **敌人**：远处首先读作剪影，进入灯区后才显示完整材质；不同物种使用穷举 motion profile。
- **环境**：主场景使用本作专属 `afterlightTerrain` 连续地形和 `afterlightRidge` 背景脊线，不再把 1×1 草地/道路 tile 当作最终世界表面。信号屋重做为不对称的低矮服务站体量；所有环境细节必须在 160px 宽场景缩略下仍能形成“大块—空地—大块”的节奏。
- **连续大地面**：`afterlightTerrain` 只能有一个承重地基和一块连续草地顶面；道路、步道、排水沟和电缆是贴地或嵌入表面层，高差不超过 0.04u。禁止用独立草台、断裂高坡和多块土基围着道路拼接。地表变化通过道路走向、大片明度区和少量排水构件表达，不靠碎石、草簇或边缘断面填充。
- **建筑精度**：主信号屋至少包含基座、主墙体、侧翼、两级屋顶、檐口、门洞纵深、窗框/窗台、雨棚或排水、外置配电箱和屋顶中继冠；每个结构的厚度不小于 0.125u。工作区增加独立维修棚，以开放工作口、起重横梁和工具墙形成第二建筑身份，但不得在搜救镜头抢走信号屋的唯一暖光。
- **导出**：正式资产使用 `<category>__<id>.glb`；预览 PNG 512×512 透明；不得改名丢失来源。

## 7. UI and icons

- **图标**：同一套 24px 自绘线性 SVG，2px 圆角线帽；电力、食物、废料、士气、时间、帮助和声音共享相同 viewBox。
- **界面母题**：采用“卡通街区防线 / Neighborhood Toy Defense”。以现代休闲经营手游的扁平粗描边与高信息清晰度为主，叠加轻量塔防的玩具面板、奶油色托盘和短距离按钮底托；不复制具体图标、角色卡、城堡、废土飞机或资源布局。UI 应像同一套可触摸的桌面玩具组件，而不是工程终端。
- **调色板**：Cream `#F7D9AD`、Cream Light `#FFF0CF`、Cocoa Outline `#493644`、Sky Button `#43BCEF`、Sky Deep `#167DB8`、Leaf Success `#78D55B`、Sun Token `#FFC94D`、Coral Alert `#EF6B68`、Plum Reward `#B85BDC`。暗场正文仍保持至少 4.5:1 对比。
- **表面层级**：一级信息使用暖奶油面板，二级信息使用浅桃木托盘；危险信息用珊瑚红顶边，生产/供电用叶绿色或天空蓝。面板统一使用近 2px 深可可紫外框、1px 内分隔、暖白内高光和 3–5px 底托，不用毛玻璃；外框、底托和内高光的粗细必须跨阶段牌、资源托盘、任务条、人物卡、按钮与结算卡保持一致，禁止每块组件各自堆一套粗阴影。
- **按钮**：主行动最小 52px 高，使用天空蓝凸起键、深蓝底托和顶部弧形高光；按下时向下移动 3px并收起底托。成功使用叶绿，危险使用珊瑚红，禁用使用灰蓝并保留原因文字。
- **HUD**：阶段签像带双铆钉的日期牌；帮助和声音是独立蓝色方键；四项资源位于一块奶油色资源托盘内，图标按语义着色，数字优先、标签次级。进度为资源托盘底部的绿色填充槽。
- **任务层级**：当前任务是奶油色任务条，步骤端用珊瑚红标签；角色对白是带大幅 GLB 胸像的浅色人物卡。二者形状与位置不同，也不得复述同一句话。
- **引导**：每步由“镜头切到人物/目标 → 人物动作或场内呼喊 → GLB 胸像短对话 → 唯一目标脉冲”组成。胸像在 390px 屏宽使用约 136×174px 舞台，窄屏仍保持可辨识的半身构图；对话正文至少 16px，最多两行中文或三行英文。
- **披露节奏**：采用“一个焦点退出，下一个焦点进入”的接力。场内呼喊退出后人物卡进入；人物卡退出后任务条与目标进入；目标独立 900ms 后操作控件进入。分工的工作台先于居民卡，生产奖励先于下一步对白，黄昏场景先于守夜卡，结算标题先于统计、统计先于重玩。资源托盘随 1–3 个已解锁资源扩展，不提前绘制空格、锁头或未来资源图标。
- **人物通讯**：人物卡使用奶油正文舱和按角色区分的彩色头像底板。乔使用 Sun Token，林使用 Sky Button；战斗短通讯压缩高度但沿用同一头像底板与深描边。
- **结算**：结算是一块从底部弹出的“夜间成绩牌”，标题居中或左对齐均可，但三项统计必须像独立计分格；成功用叶绿徽章，失败用珊瑚红徽章，不只靠颜色传达。
- **状态**：默认、按下、键盘焦点、禁用、加载、成功、警告均有形状或文本差异；焦点使用 2px 暖白外框。
- **Emoji 政策**：功能 UI 永不使用 Emoji。

## 8. Motion and VFX

- **动效性格**：界面按钮像玩具按键一样快速下压回弹；电力传播仍快速、分段、确定；居民动作稍有弹性，怪物动作更重、更不对称。
- **时间令牌**：快速确认 120–180ms；面板进入 220ms；世界变化 420–650ms；重大完成 900–1400ms。
- **命中/奖励**：日常产出只显示合并数字；职业匹配产生 6 个方形粒子；路障破裂才允许 3px 震动。
- **粒子**：圆角星点、短线和低多边形碎屑；不使用写实烟花或全屏彩屑。
- **过载峰值**：输入同帧启动一次不超过 4.2 zoom 的短促镜头推进；两盏中继灯周围只允许 12 根细短方柱上升，结束后立即隐藏。`prefers-reduced-motion` 下取消镜头推进与上升短线，保留灯色、真实照明、按钮状态和导管传播。
- **灯光过渡**：环境光、半球光、主光和局部点光使用阻尼过渡，黄昏与灯具启动不能整场硬切；背景色可快速切到夜值，但主体照明必须在约 180–420ms 内完成衰减或点亮。
- **降低动态效果**：取消相机推拉和震动，将线路动画压缩为 120ms 透明度变化；所有状态仍可读。

## 9. References translated into principles

- **《Kingshot / 奔奔王国》**：采用“一个动作后才开放一个新系统”的渐进教学；不复制其界面、角色、建筑、数值和付费结构。
- **共享 low-poly 资产库**：采用正交等距、硬边三值光和统一 teal 家族色；不把库存模型重绘成另一种光照语言。
- **两张休闲手游参考图**：采用奶油色玩具面板、短硬阴影、深描边、凸起蓝键、绿色完成态、红色提醒态与资源分色；不复制其波次牌、城堡、英雄卡、飞机残骸、底部导航、资源名称和关卡构图。

## 10. Anti-patterns

- 禁止中世纪城墙、王冠、盾徽、卷轴与《Kingshot》近似构图。
- 禁止渐变霓虹、泛光描边、玻璃卡片、无边界胶囊和无含义装饰网格；允许视觉系统规定的圆角玩具面板。
- 禁止 Emoji 功能图标、混用填充与线性图标、照片头像贴在三维模型世界上。
- 禁止把 512×512 全身透明预览图裁进 50–100px 头像框，或用 CSS 暴力放大冒充角色立绘。
- 禁止同时显示多个教学箭头、长段说明、未到时机的系统入口和整屏不可跳过教程。
- 禁止固定远景覆盖所有阶段；禁止人物不演、只靠旁白卡解释“这里发生了什么”。
- 禁止用临时方块冒充发电机、岗哨等最终关键资产。
- 禁止棋盘式重复铺地、每格一块石头/一簇草，以及在开场提前陈列尚未教学的设施。
- 禁止把“大地面”理解为放大旧地块：不能保留多块草台轮廓、露土断面或明显拼缝；道路必须读作切入同一地表的功能区域。
- 禁止建筑只由“墙盒＋一块屋顶＋贴片窗”构成；主建筑必须在正面和屋顶轮廓上同时拥有结构层次。

## 11. Vertical-slice acceptance

- **进入**：5 秒内理解目标是恢复发电机周边街区，并可跳过或重播教学。
- **经营**：完成一次搜救和一次岗位匹配；场景、资源与居民状态同时产生可见变化。
- **高反馈**：修复路障或点亮设施时，电力线路、暖灯和声音同步完成。
- **守城**：经历 35–45 秒第一夜，能使用一次路灯过载，并看懂失败原因。
- **窄屏**：320×568 下场景主体不被 HUD 遮挡，主要按钮不小于 44px，中文和英文均不截断。
- **视觉 QA**：390×844 与 320×568 两轮 matched platform-layout 截图无 P0/P1；另保留 external-guest 发布检查。
