# 屏幕与状态合同

## 全局环境

- **界面类型**：响应式 DOM HUD + 自适应 Three.js 场景的混合界面。
- **目标尺寸**：390×844 与 320×568，竖屏；桌面仅居中展示手机比例。
- **输入**：触控、鼠标 Pointer；键盘仅作可访问与调试补充。
- **平台覆盖**：平台内无访客栏；顶部和底部分别尊重 `safe-area-inset-top/bottom`。
- **持久元素**：顶部铆钉阶段牌、右上角两枚蓝色工具键、右下角单色 AlterU 水印。资源托盘不是开局常驻信息，按当前已使用的资源逐项解锁。
- **当前任务**：教学步骤在 HUD 下方只显示一条“步骤编号＋行动句”，不承担剧情叙述；剧情和人物动机由角色对白承担。

## 状态序列

| 状态 | 玩家此刻的问题 | 主焦点 | 唯一主行动 | 退出条件 |
|---|---|---|---|---|
| `boot` | 游戏能否开始？ | 发电机微光 | 等待模型加载 | 必需 GLB 成功或进入可恢复错误 |
| `intro` | 我为什么在这里？ | 黑暗街区与发电机 | “接通余光” | 点击开始或跳过教学 |
| `rescue-guide` | 我先做什么？ | 闪烁的被困居民 | 点击搜救点 | 搜救开始 |
| `rescuing` | 行动是否生效？ | 8 秒搜救进度 | 等待，可取消教学提示 | 居民出现 |
| `assign-guide` | 新居民能做什么？ | 工人与工作台 | 拖动工人到工作台 | 成功落位 |
| `production-proof` | 分工带来了什么？ | 废料产出与通电线路 | 点击“继续修复” | 首次产出完成 |
| `repair-guide` | 如何准备防守？ | 路障破损段 | 点击修复 | 路障恢复并进入黄昏 |
| `dusk` | 夜里会发生什么？ | 两条敌路与倒计时 | 选择路灯过载 | 选择后或 12 秒结束 |
| `defense` | 哪里快守不住？ | 敌人、路障、核心 | 在提示时触发过载 | 敌群清空或核心归零 |
| `slice-win` | 我的选择有什么结果？ | 亮起的街区 | “再守一次” | 重新进入 intro 或自由模式 |
| `slice-fail` | 为什么失败？ | 破损位置与原因卡 | “调整分工重试” | 回到 assign-guide 前状态 |
| `asset-error` | 为什么看不到游戏？ | 错误说明 | “重新加载模型” | 重试成功或留在可读错误态 |

## 引导合同

- **Aha 时刻**：工人落到工作台后，人物开始工作、废料增加、电线与设施同时亮起。
- **渐进披露**：教学步骤固定为四个注意力拍：场内演出；演出退出后出现人物卡；玩家点击查看后人物卡退出并出现任务/目标；目标独立 900ms 后才出现唯一真实操作。自动计时只分隔信息，不推进 gameplay phase。
- **全局接力**：分工先显示空工作台，再显示居民卡；生产先显示 `+3`，再显示资源托盘与对白；黄昏先显示灯区，再显示守夜卡；夜战先显示口令，再显示技能；结算先显示结果，再显示统计，最后显示重玩。
- **资源解锁**：搜救只显示电力；分工第二拍加入废料；夜战加入士气；食物等到厨房系统首次出现。未解锁资源不保留空槽，也不使用问号占位。
- **示范**：玩家点击“查看信号屋 / 工作台 / 南路路障”后，镜头对准目标，目标对象使用地面脉冲环示意；示意不得遮住对象。分工第二段同时显示工作台插槽与唯一居民卡，因为二者共同组成一次拖拽动作，不视为两个竞争操作。
- **练习响应**：错误拖放立即回弹并显示“工人更适合工作台 100% / 其他岗位 55%”，不扣资源。
- **完成判定**：玩家完成真实动作即永久关闭对应提示，不要求点击“知道了”。
- **可跳过与重播**：介绍页可跳过；帮助按钮可从当前步骤重播，不重置游戏资源。
- **回流玩家**：本地记录已完成步骤；超过 7 天未进入时，仅恢复一条上下文提示，不重放开场。

## 卡通塔防 UI 组件合同

- 顶部第一行：左侧阶段牌使用奶油面、珊瑚顶边和双铆钉；右侧两枚蓝色玩具键只承载帮助和声音。防守倒计时附着阶段牌，不另开卡片。
- 顶部第二行：已解锁资源合并为一块会随数量扩展的奶油色托盘，1 / 2 / 3 项宽度分别约 102 / 196 / 286px。数字最多四位，图标按电力/废料/士气分色；绿色进度沿底部槽传播。教程不得提前显示无用途资源。
- 教学步骤使用浅色任务条：珊瑚步骤标签 + 一行动词句；同屏不得再出现第二张规则说明卡。
- 剧情对白使用人物卡：左侧 GLB 胸像置于角色色底板，右侧姓名、台词与可选蓝色主键；乔/林分别用暖黄和天蓝识别。
- 底部居民调度使用一张可拖拽英雄式岗位卡，头像、职业、技能与岗位图标分为三栏；不展示尚未解锁的居民卡组。
- 夜战技能是底部蓝色凸起技能键；战斗短通讯位于其上方，使用压缩人物卡。
- 结算使用底部奶油色成绩牌，三项统计为独立计分格，不使用深色工程报告。
- 中间 62% 场景不放固定面板；提示贴近世界对象并用短句说明动词。
- 高危险事件暂时压暗顶部非关键资源，仅突出核心耐久和被攻击路径。

## 人物演出与空间合同

- 剧情对白使用正式 GLB 离线渲染的透明胸像：头、肩、上半身占立绘框 85% 以上，禁止继续使用全身缩略图或放大全身 sprite 冒充立绘。
- 立绘从对话框底边自然溢出，姓名与台词位于独立文字区；角色身份色沿用乔的暖金与林的青色，不另造头像风格。
- 被困角色在房门开启前不渲染实体模型；破门进度达到 72% 后，林只在门外安全点出现。乔、林、工作台和建筑各自保留至少 0.35 世界单位的视觉间隙。
- 每次修改建筑或人物比例后，必须在 `rescue-guide`、`rescuing`、`assign-guide` 三个状态复查脚底接地、门框遮挡和模型穿插。
