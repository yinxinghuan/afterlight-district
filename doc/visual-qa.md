## Iteration findings and fixes

1. P1，角色站位：动作起伏覆盖了世界 Y，人物像陷入地面。修复为外层世界变换 + 内层演出变换，并恢复正式 rest pose。
2. P1，救援构图：气泡、搜救按钮和人物互相遮挡。按钮移出气泡，林退到门内、乔移到门外，形成受困者—施救者关系。
3. P2，动作同质化：`signal / point / work / shamble / prowl` 分别使用挥手、稳定指向、双臂工作、非对称拖步与低伏疾行。
4. P1，夜景扁平：原实现只有基础光与埋在连续地面下方的 `ContactShadows`。改为 GTAO、2048² 方向软影、冷 fill、暖 rim 和 1.04–1.07 exposure；屋檐、窗框、梁柱与地面交界恢复深度。
5. P2，过载像颜色切换：增加一次 4.2 zoom 短推进、两灯 12 根短方柱、实际点光增亮和 8 段导管传播；降低动态效果时取消镜头和短线。
6. P1，门状态缺乏物理因果：废弃无滑轨的侧滑方案，改为前半段斜撑落地、后半段真实铰链开门。终态斜撑最低点 `0.1486u`，地基顶 `0.14u`，接地误差约 `+0.009u`；独立美术复审 PASS。
7. P1，UI 层级混杂：资源、剧情、操作提示同时竞争注意。资源压缩为 38px 状态轨，新增单行当前任务；对白只保留人物动机，世界按钮只保留动词。
8. P1，立绘像全身缩略图：停止裁切 `models/*.png`，从正式 Jo/Lin GLB 以正交相机、三点光离线渲染 512×512 胸像；390px 对话舞台约 136×174px，320×568 仍保留 102×130px。
9. P1，人物穿插：被困阶段不渲染林的实体；破门 72% 后只在门外右侧出现，乔移到门外左侧；工作状态调整到工作台道路侧。`rescuing-emergence` 证据显示门、乔、林之间均有可读间隙。
10. P1，地面仍像碎板：废弃多块高差草坡，重建为单一 15×18u 地基与连续顶面；正式 390×844、320×568 的搜救、黄昏、战斗和结算镜头均看不到外缘或土基断面。
11. P1，道路像贴片：支路缩为通往维修棚的 5.8u 接驳和前坪，交叉口使用独立 junction patch；肩线改成短分段，道路表面厚度降至 0.025u。
12. P1，建筑精度不足：信号屋新增双坡屋顶、深门洞、雨棚、窗框窗台、配电与屋顶设备；新增维修棚的开放工作口、工具墙、屋顶监视器、行车和吊钩。v4 独立复审 PASS。
13. P1，低帧率倒计时拉长：防守 `dt` 上限由 0.05s 调整为 0.25s；两尺寸完整流程均能在测试时限内进入结算。
14. P1，人物方向影抢焦点：第一轮把角色设为 `castShadow=true` 后，救援反打机位出现横跨草地的大黑影。复审后恢复角色不投射长方向影，保留 GTAO 接地；matched recheck 中黑影消失。
15. P1，过载灯芯烧白：第一轮 Bloom 0.38、阈值 0.72 与强度 22 点光叠加，灯具结构丢失。最终 Bloom 降至 0.14、阈值 0.92，过载点光降至 18、脉冲 8%，仍保留白芯但黑色灯翼和地面渐变可见。
16. P2，大地面仍像单色板：只为跨度至少 4u 的正式地形表面克隆材质，叠加约 6% 值差、无写实噪点的程序化宏观贴图；没有改写共享 GLB 原材质真源。
17. P2，机位仍像同一沙盘：除救援反打外，工作、路障、黄昏和守城分别获得不同高度/方位 offset；黄昏 zoom 83、守城 82，主体更大但 390×844 与 320×568 均不露地形外缘。
18. P1，UI 角色不清：旧版 HUD、任务、对白与结算都像同一种浮层，玩家需要先读文字再猜功能。重做为 Civic Relay Console：状态使用窄资源脊，任务使用暖色票据，角色对白使用大幅通讯窗，居民使用可拖拽工单，过载使用实体供电键，结算使用高对比夜间报告。
19. P1，窄屏派工通讯窗过重：第一轮在 320×568 下人物立绘占用过大。将顶部通讯窗的立绘槽缩至 82×108px、文本区左边距缩至 96px；任务插槽的伪元素文字改为无语义的双段信号条，避免绕过 i18n。
20. P1，界面气质偏硬核：前一版深色工程终端与用户提供的休闲手游参考相距较大。重构为“卡通街区防线”：奶油色实体面、2px 深可可紫描边、暖白内高光、天空蓝凸起键、叶绿完成态与珊瑚警告态；没有复制参考图的具体图标、关卡、角色卡或建筑。
21. P1，浅色卡片可能压住夜景：在 390×844 的救援、派工、夜战、过载和结算状态复查。界面只占顶部信息区和当前行动区，中部道路、建筑、敌人和真实灯光保持可见；战斗技能默认蓝色、可用时绿色、使用后灰蓝，同时保留状态文字。
22. P2，320×568 人物卡留白过多：首轮新皮肤仍被后置通用规则抬回 160px。最终显式限制普通人物卡 132px、顶部派工卡 126px，头像槽 90×112px / 82×98px；matched recheck 中台词、姓名和半身立绘均无裁切。
23. P2，派工截图个别资源字形在预览缩略中缺失：独立 Playwright DOM 审计确认四项资源 `36/30/25/60` 均存在、每格 72×37px、文字为深色可见状态；判定为图像预览采样而非产品 DOM 缺失。
24. P2，英文窄屏控件宽度复核：通用 `scrollWidth` 检查最初标记 `Start rescue` 与 `Workbench · 100% match`，逐节点复核确认差值来自 `inset:-9px/-8px` 的绝对定位脉冲环，而非文字裁切；页面仍为 `320/320px`。同时把行动键与岗位插槽分别扩至 154px 和 174px，为英文标签保留更稳定的内部余量。
25. P1，3D 轮廓锯齿：原 Canvas 虽启用 `antialias:true`，但 EffectComposer 离屏管线没有 MSAA/SMAA，且 DPR 上限为 1.6。新增三档质量与 `SMAAPass`；模拟 DPR 3 的 390×844 证据中，low 缓冲为 487×1055（约 1.25×），high 为 780×1688（2×），档位解析均与请求一致。low 关闭 Bloom、GTAO 6 samples、1024² 阴影；high 使用 4× MSAA、12 samples GTAO 和 2048² 阴影。
26. P2，静态硬件判断可能误判：新增实际帧率 governor；连续两个 4 秒窗口低于 42 FPS 才降一级，跳过后台和大于 250ms 的恢复帧。`?render_quality=` 锁档时 governor 不介入，保证 matched QA 可重复。
27. P1，漫画线范围过大风险：没有给地面、道路、远景和所有设施统一勾边。以 `target / actor / landmark` 三类显式标记选择对象；low 只保留当前目标，balanced 增加人物和敌人，high 增加主信号屋。救援、派工、夜战和过载证据中，中部道路与草地保持无轮廓留白。
28. P1，首轮 OutlinePass 混合错误：默认 OutlinePass 为加色发光设计，首次改成 Multiply 后选择遮罩内部被整体压黑。matched recheck 改为 NormalBlending、无 glow，模型原材质与灯光恢复，仅边缘像素着色。
29. P1，轮廓在交付截图中不可辨：前一版 high 约 1 CSS px、颜色 `#332832`，代码虽然启用但缩到手机宽度后视觉上近似消失。最终改为近黑紫 `#100E12`、strength 1.6，high / balanced / low thickness 为 4 / 3 / 3.2；390×844 救援和夜战、320×568 救援与派工截图中，目标建筑、人物和敌人不放大即可辨认，同时道路、草地仍无黑线，中继灯 Bloom 未被覆盖。
30. P2，休闲 UI 仍有组件拼装感：统一阶段牌、资源托盘、任务条、人物卡、按钮、居民卡和结算卡的外框、内分隔、暖白高光与 3–5px 底托；资源图标改为语义分色底章，姓名签与状态签共享同一描边尺度，主键/禁用键/结果键使用一致的按压深度。两尺寸复查后不再出现某些卡片 6–8px 重底托、另一些只有细边的混杂感。
31. P1，前期信息一次性倾倒且自动披露仍令人费解：原搜救步骤同屏立即出现阶段、四资源、任务条、对白、场内呼喊和行动键；首轮修复改为自动三拍，但玩家仍需被动等待并判断何时能操作。最终改为动作驱动两段式：第一段只有人物情境和“查看目标”，点击后人物卡收起，第二段只保留任务与唯一真实操作；资源继续按用途逐项解锁。matched evidence 覆盖 390×844 的 `rescue-context / rescue-guide / repair-context / repair-guide` 与 320×568 的 `assign-context / assign-guide`，0 findings。
32. P1，教学镜头推得过近：旧救援/工作/修复 zoom 为 106–118，人物、目标与周边道路无法同时建立空间关系。最终调整为救援 88–92、工作 90–94、修复 88，黄昏/夜战 76；390×844 与 320×568 复查均能同时看到角色、完整目标和周边道路，地形外缘仍未进入主画面，夜战敌人和灯区保持可辨。
33. P1，全局信息仍在阶段切换时成批进入：对搜救、分工、首次产出、修复、黄昏、技能教学与结算逐项做新增信息审计。最终建立场内演出→人物卡→目标→操作接力；分工目标先于居民卡 900ms；`+3` 奖励退出后才显示对白；黄昏灯区先于人物卡；技能直到口令后开放；结算按结果/统计/重玩三拍显示。matched evidence 覆盖两尺寸前期流程以及 390×844 修复、黄昏、夜战、结算，`capture-findings.json` 为 0 findings。
34. P1，正确分配后人物瞬移到工作台：原 `assignWorker()` 同帧写入 `assigned=true`，场景位置直接从门外切到岗位，只有到岗后的 `work` 肢体循环，没有走过去的因果演出。新增独立 `assigning` phase、2.8 秒转身/三段开放路径/到岗转向、普通人反相步态和五个路径脚步点；到岗前不点亮供电、不增加废料、不显示生产对白。首轮路径从屋后经过，角色被维修棚屋顶遮住且文字进度卡抢占视线；matched recheck 将起点移到开放道路集合点并取消文字卡。第二轮又发现绝对墙钟在低帧率下会一帧跳到终点，最终改为单帧最多推进 100ms。`_qa/ui/assignment-motion/report.json` 在 390×844 的 10.7% / 35.7% / 64.3% / 92.9% / 工作五帧、320×568 中点/工作和 reduced-motion 中点共 8 份证据中返回 0 findings；完整拖拽流程两尺寸与 external-guest 复查同样为 0 findings。

- Build：`npm run build` PASS；仅保留 Three.js 主包大于 500kB 的非阻断警告。
- Portability：构建产物无根绝对 `src / href / url()` 路径。
- Inventory：`sync-inventory.mjs` read-only PASS，98 assets / 15 scene assets。

## Final recommendation

当前场景、人物演出、教学 UI 与分档渲染管线已达到可继续扩充内容的成熟基线。下一轮新增系统时应沿用本轮三值光、分档 GTAO、SMAA 和受控灯光阈值，不增加常驻文字卡；场景规模扩大前应完成真实低端 Android 与高端 iOS 的长时热降频验证，而不是再次以压暗曝光掩盖性能或氛围问题。
